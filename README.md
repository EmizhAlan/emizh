# emizh

**emizh** — персональный конструктор сайта на PHP. Владелец редактирует свой сайт через браузер, посетители видят готовые страницы. Весь контент хранится в одной папке `data/`, логин и пароль — в отдельном файле `owner.json` вне корневой директории сайта.

Проект рассчитан на одного человека, который ведёт небольшой личный сайт и не хочет использовать крупные системы управления. Здесь нет плагинов, тем на выбор, ролей, комментариев и баз данных — только то, что действительно нужно.

## Возможности

- Редактирование страниц через браузер, без залезания в код
- Содержимое страниц в формате markdown
- Один владелец: логин и пароль создаются один раз и не теряются
- Настройка названия сайта, акцентного цвета, шрифта и темы
- Управление порядком страниц в навигации
- Полный сброс сайта одной кнопкой
- Работа на стандартном shared-хостинге с PHP 8.0 или выше

## Как это работает

Идея проекта строится на разделении двух независимых сущностей:

1. **Владелец** — описывается файлом `owner.json`, в котором лежат логин и хэш пароля.
2. **Контент** — лежит в папке `data/`: настройки сайта и все страницы.

Эти две части полностью независимы. Удаление папки `data/` не затрагивает вход в панель управления. Замена `data/` на чужую не меняет логин. Файл `owner.json` и папка `data/` размещаются **на уровень выше `public_html/`**, что делает их физически недоступными из браузера.

Если папки `data/` не существует (например, вы её удалили), приложение воссоздаёт её из эталона `defaults/` — с дефолтной темой и двумя демонстрационными страницами. Это позволяет в любой момент «сбросить» сайт до исходного состояния.

## Требования

- **PHP 8.0 или выше** (проверено на 8.4)
- **Apache** или эквивалентный сервер с поддержкой `.htaccess`
- Права на запись в директорию, в которой лежит `public_html/` (для создания `data/` и `owner.json`)

Внешние библиотеки, Composer, npm, фреймворки — **не требуются**.

## Установка

### 1. Скачать проект

Склонировать репозиторий:

```bash
git clone git@github.com:EmizhAlan/emizh.git
cd emizh
```

Или скачать архив релиза с GitHub: https://github.com/EmizhAlan/emizh/releases

### 2. Собрать папку поставки

```bash
php tools/make-dist.php
```

После этого появится папка `dist/` с готовым приложением.

### 3. Загрузить на хостинг

Скопировать **содержимое** `dist/` (не саму папку) в `public_html/` на хостинге.

На хостинге структура должна выглядеть так:

```
/home/user/
├── public_html/          ← сюда распаковано содержимое dist/
│   ├── assets/
│   ├── classes/
│   ├── defaults/
│   ├── .htaccess
│   ├── bootstrap.php
│   ├── index.php
│   └── VERSION
├── data/                 ← создастся автоматически
└── owner.json            ← создастся при регистрации
```

### 4. Открыть сайт

Перейти по адресу сайта. Появится дефолтная главная страница.

### 5. Создать владельца

Перейти на `/admin`. Приложение предложит создать логин и пароль. После регистрации файл `owner.json` появится рядом с `public_html/`.

## Структура

### Репозиторий

```
emizh/
├── src/                  # исходники приложения
│   ├── assets/           # стили и скрипты
│   │   └── app.css
│   ├── classes/          # классы логики
│   │   ├── Page.php
│   │   ├── Site.php
│   │   ├── Storage.php
│   │   └── Version.php
│   ├── defaults/         # эталон дефолтного сайта
│   │   ├── pages/
│   │   │   ├── about.json
│   │   │   └── home.json
│   │   └── site.json
│   ├── .htaccess         # правила Apache
│   ├── bootstrap.php     # автозагрузчик классов
│   ├── index.php         # точка входа (читатель)
│   └── VERSION           # текущая версия приложения
├── tools/
│   └── make-dist.php     # скрипт сборки
├── screenshots/          # иллюстрации для документации
├── README.md
├── CHANGELOG.md
├── LICENSE
├── .gitignore
├── .gitattributes
├── data/                 # не в git, создаётся автоматически
└── dist/                 # не в git, создаётся сборкой
```

### Поставка (`dist/`)

Содержимое папки `dist/` полностью повторяет содержимое `src/`. Единственное отличие — она очищена от служебных файлов репозитория (`.git`, `README.md`, `tools/`).

### Папка `data/`

```
data/
├── site.json             # настройки сайта
├── pages/                # все страницы
│   ├── about.json
│   └── home.json
└── uploads/              # зарезервировано под будущие загрузки
```

### Файл `owner.json`

```json
{
  "username": "admin",
  "passwordHash": "$2y$10$...",
  "secret": "случайная-строка-для-сессий"
}
```

Пароль хранится только в виде хэша. Восстановление — только вручную через правку файла.

## Безопасность

- **Файл `owner.json` и папка `data/` вне `public_html/`.** Они физически недоступны по HTTP — браузер не может даже запросить их.
- **Пароль в виде хэша.** Используется стандартная функция `password_hash()` с алгоритмом bcrypt.
- **CSRF-токены для всех POST-форм.** (В текущей версии — планируется в v0.3.0.)
- **Строгая валидация слагов.** Разрешены только строчные латинские буквы, цифры и дефис. Любые попытки передать `../` отклоняются.
- **`.htaccess` защищает служебные папки.** Прямые запросы к `/classes/`, `/defaults/` и `/bootstrap.php` возвращают 404.
- **Отключён листинг директорий.** Никто не увидит список файлов в папке.

## Обновление

Чтобы обновить до новой версии:

1. Скачать новый релиз.
2. Собрать `dist/`.
3. Скопировать содержимое `dist/` поверх существующих файлов в `public_html/`.

Файл `owner.json` и папка `data/` при обновлении **не затрагиваются** — они лежат отдельно.

---

## Резервная копия

Резервная копия сайта — это просто копия папки `data/`. Сохраните её в любом месте. Для восстановления — верните папку на прежнее место.

Файл `owner.json` тоже стоит сохранить — иначе после восстановления придётся создавать владельца заново.

---

## Перенос на другой хостинг

1. Скопировать с прежнего хостинга три вещи:
   - содержимое `public_html/`,
   - файл `owner.json`,
   - папку `data/`.
2. Разместить их в соответствующих местах на новом хостинге.
3. Убедиться, что на новом хостинге PHP 8.0 или выше.
4. Открыть сайт и проверить вход в панель управления.

## Разработка

### Локальный запуск

Проект можно запустить локально через любой стек с PHP 8+ (XAMPP, Laragon, MAMP). Например, в Laragon: разместить проект в `C:\laragon\www\emizh\`, открыть в браузере `http://localhost/src/`.

### Сборка

```bash
php tools/make-dist.php
```

Проект использует [Semantic Versioning](https://semver.org/lang/ru/) и [Conventional Commits](https://www.conventionalcommits.org/ru/).

Формат коммитов:

```

fix: исправлена валидация слагов
docs: обновлён README
chore: обновлён .gitignore
refactor: вынес markdown-парсер
```
